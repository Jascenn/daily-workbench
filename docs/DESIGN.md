## 2026-10-03 多页面视觉统一 v2

### 1. Visual theme and atmosphere

暖白编辑台。页面像一组长期使用的个人工作簿，而不是同尺寸卡片组成的后台模板。每个功能页先回答一个问题，再展示证据；留白集中在区块之间，数据行内部保持紧凑。

### 2. Color palette and roles

- Canvas: `--bg`, 工作区底色。
- Surface: `--card`, 只用于需要独立边界的内容区。
- Ink: `--ink`, 标题和主要数据。
- Muted: `--muted`, 来源、口径和解释。
- Primary: `--accent`, 全局选择、链接和主动作。
- Editorial accent: `--workspace-accent:#9b451f`, 页面序号和当前任务，不承担成功或失败语义。
- Status: `--ok / --warn / --pos / --neg`, 只表达真实状态。

### 3. Typography rules

继续使用系统 Latin + PingFang SC 字体栈，不增加联网字体。页面标题使用 `--fs-2xl`、700，区块标题使用 `--fs-lg`、700，正文使用 `--fs-base`，辅助信息使用 `--fs-xs`。所有数字继承 tabular nums；中文标题不使用负字距。

### 4. Component stylings

- Page header: 无卡片、无阴影，以 eyebrow、标题、说明和右侧来源组成。
- Metric rail: 透明背景、发丝线分组，不再把每个数字包装成独立卡片。
- Content section: 仅在内容确实需要独立边界时使用 `.card`，去掉默认阴影。
- Buttons: 保留现有固定圆角与语义色，按下时 `translateY(1px)` 或 `scale(.98)`。
- Disclosures: 次要历史和口径使用原位展开，不使用模态。

### 5. Layout principles

统一顺序为 page header、source strip、metric rail、primary work area、supporting detail。桌面端主体允许 1.55:1 双列；区块间距使用 24px，行内使用 8px 或 12px。页面不通过增加卡片数量填补空白。

### 6. Depth and elevation

默认用背景明度和 1px 发丝线分层。内容卡无阴影；只有全局浮层、通知和真正悬浮的操作菜单使用 `--shadow-md / --shadow-lg`。深色主题使用表面亮度阶，不依赖黑色阴影。

### 7. Do and do not

- Do: 每页只设一个主问题；数字左标签右数值；来源紧跟页头。
- Do: 保留真实数据边界，未知不显示为 0。
- Do: 长列表先显示最相关范围，再提供完整视图。
- Do not: 重复四张或八张同权 KPI 卡。
- Do not: 用粗侧边线、渐变文字、玻璃效果或装饰性图标制造层级。
- Do not: 为统一视觉改变数据口径、同步路径和本地存储行为。

### 8. Responsive behavior

980px 以下双列变单列；560px 以下 metric rail 变两列，页头来源独占一行。导航保持单行横向滚动，交互目标有效命中区至少 40px；输入框在 iOS 保持 16px，避免自动缩放。

### 9. Agent prompt guide

- `canvas: var(--bg)`, `surface: var(--card)`, `ink: var(--ink)`, `muted: var(--muted)`, `primary: var(--accent)`, `editorial: #9b451f`.

## 0. 方向与不可让步的四件事

四件事同时成立，才决定了后面所有取舍：

1. **下一步是主角，金额是证据。** 首屏先回答三个问题：推进哪个项目、先处理哪条经营异常、
   本月目标还差多少。KPI、目标带和账本仍保留完整信息，但不能挡在行动之前。
   「数字对齐」「单位一致」「红涨绿跌」仍是正确性，不是装饰。
2. **红=收入/涨、绿=支出/跌**（中国股市惯例，与欧美相反）。
   这条不是偏好，写错会直接读反结论。语义色因此**同时承担文字职责** → 对比度必须按 4.5:1 要求，
   不能按"非文字 3:1"放宽。
3. **账本有 257 行且每月增长。** 任何"让单行更高一点"的改动都会乘以 257。
   这一条否决了若干标准做法（见 §8 反向约束）。
4. **「总览」只是八种类型之一。** 另外七种：**资讯 / 写作 / 复盘**（上游派生快照）、
   **项目**（真实 `state.projects`，来自 Notion「项目管理」只读同步）、
   **客户**（真实 `state.clients`，来自 Notion「贵人计划」；未连接时才回退本地试验区），以及
   **时间 / 内容**（本地 `localStorage` 试验区，必须显式标注，不得冒充真实数据）。
   原因就是凌一那句「这个属于记账 还有写作 资讯等啊」—— 工作台原先 100% 是账本，
   而它要回答的问题不止"钱从哪来"。这条约束的形态很特别：
   它不是"再加几个卡片"，而是要**在不破坏第 3 条的前提下**把完全不同形态的数据
   （条目流 / 章节树 / 周复盘组 / Kanban / 贵人漏斗 / 番茄钟 / 内容流水线）塞进同一套骨架里 ——
   所以复用 `.seg` 做切换器、复用 `.card/.kpi/.tag` 做容器，一处新视觉都不引入（见 §4.1）。
   项目与客户、时间、内容都在 `renderSections` 里早返回，**不进 `sections.json`**；项目读 `state.projects`，
   客户读 `state.clients`（无 Notion 数据时才回退本地样例），时间/内容读本地样例，
   因此不污染资讯/写作/复盘三区的 days/窗口/排序口径。

## 2. 排版规则

- 正文 **14px / 行高 1.5**（实测 21px）；表格 13px；表头与辅助信息 12px；**全页无 <12px 字号**（6 档收敛前有 7 处在 10–11.5px）
- 标题层级：`h1` 20px/700（实测 30px 行高）、`h2` 16px/700（24px 行高）；层级最多到 `h3`
- 中英混排：系统栈 Latin 在前，`lang="zh-CN"`
- **数字一律等宽**：`body{font-variant-numeric:tabular-nums}`。这是金额应用，账本/来源排行/KPI/达成史全是数字列，非等宽会导致竖排对不齐、扫读时位数跳动
- 金额保留 2 位小数；分位精度不得被 `round` 破坏（有用例守着：收入合计 26958.4870）
- 长标题开 `text-wrap: balance`、正文开 `text-wrap: pretty`

## 3. 色彩纪律

**实测对比度**（WCAG 2.1 相对亮度程序化计算，非目测；`✓`≥4.5，`△`≥3 仅合格于非文字）：

| 组合 | 亮色 | 暗色 | 用途 |
|---|---|---|---|
| `ink` / `card` | 15.79:1 ✓ | 14.21:1 ✓ | 正文、数字 |
| `muted` / `card` | 5.81:1 ✓ | 6.87:1 ✓ | 次级文字（标签、表头） |
| `ink` / `bg` | 14.73:1 ✓ | 15.52:1 ✓ | 页面底上的正文 |
| `pos` / `card` | 5.51:1 ✓ | 6.08:1 ✓ | 收入红 |
| `neg` / `card` | 5.44:1 ✓ | 9.67:1 ✓ | 支出绿 |
| `warn` / `card` | 5.19:1 ✓ | 10.09:1 ✓ | 警告琥珀 |
| `accent` / `card` | 5.87:1 ✓ | 5.28:1 ✓ | 主色当文字/图标 |
| 白字 / `accent` | 5.87:1 ✓ | 5.28:1 ✓ | 主按钮（改造前 4.44，卡在线上） |
| `line-strong` / `card` | 3.34:1 △ | 3.18:1 △ | 控件边框（非文字，≥3 即合格） |
| `line` / `card` | 1.20:1 ✗ | 1.27:1 ✗ | **仅**装饰性发丝线 |

规则：

- 主色只出现在：主按钮 / 选中态 / 关键链接。其余一律中性灰
- 语义色**只用于状态**，禁止装饰。且因为它们**同时当文字用**，一律按 **4.5:1** 要求（不按非文字 3:1 放宽）
- **两级边框必须分开**：`--line` 用来画好看的发丝线；凡是"要和背景划出可编辑区"的边框（input / select / textarea）必须用 `--line-strong`。改造前两者是同一个值，对比度 1.20:1 —— 输入框的边界根本看不出来
- 交互态一律从主色阶取相邻档，**禁止另调近似色**：色阶外出现第二个蓝即漂移
- **透明档不得漂移**：CSS 里每个 `rgba()` 的 RGB 必须等于某个令牌的 RGB（`rgba(59,110,245,.14)` 这种"某个令牌的透明版"必须跟着令牌一起改）。断言守着这条，例外仅限中性阴影/遮罩/斑马纹
- 暗色是令牌翻转；`--pos/--neg/--ok/--warn` 在暗色下换成高明度版本（红 #ff6b6e / 绿 #4ade80）而不是同一个色值

### 4.1 功能类型导航（2026-10-03：来源可见、按使用频率排序）

八种类型各是一个 `.screen`，同时只有一个可见；切换器就是页面原有的 `.seg/.segbtn`，
**不为新区另起一套控件外观**。导航顺序固定为：总览 → 项目 → 客户 → 时间 → 资讯 → 写作 → 内容 → 复盘。


四条不能商量的实现决定，每条都有断言守着：

| 决定 | 理由 |
|---|---|
| `.typebar` 放在 `<main>` **里面**而不是上面 | 键盘用户 `Tab` 的第一跳落在 `<main>` 起点，那里就该看见"这里有哪些类型"；放外面得反向 `Tab` 才够得到 |
| 用 `aria-pressed`，**不用** `role="tab"` | `role="tab"` 要配套方向键导航 + roving `tabindex`。只写 role 不实现键盘契约，比不写更糟 —— 屏幕阅读器会宣称一套不存在的操作方式 |
| `.screen[hidden]{display:none}` 显式写一条 | `hidden` 属性靠 UA 的 `display:none` 生效，而**作者样式优先于 UA**：哪天给 `.screen` 加了 `display:grid`，`hidden` 就静默失效（"看不见的屏还在占位"）。成本一行 |
| 选中态写进 `localStorage("wb_type")`，并且**校验合法性**：`if(!TYPES.some(...)) k="ledger"` | 手改过存储或删掉某类型后，`curType` 会指向一个不存在的屏 → **八屏全隐藏、页面看起来是空白的**。这个失败形态没有任何报错，只有一行白屏 |

- 概览数字条用 `.statgrid`（`repeat(auto-fit,minmax(170px,1fr))`），**不是** `.kpis` 的固定 `repeat(4,1fr)`：
  各类型有 5~6 个概览项，5 个塞进 4 列会剩一个孤零零掉到第二行
- 新鲜度条 `.fresh` 单独占一条放最上面（"数据有多新"是**上游三类区与项目区**的核心信息）；
  过期只靠**左侧色条 + 文字**同时表达，不靠颜色单独传达信息（WCAG 1.4.1）。
  项目区复用 `.fresh` 显示真实库名、Notion 只读状态与最近同步时间；客户连接 Notion 后用
  `.workspace-source` 显示来源与最近同步，时间/内容用 `.labnote` 明说「本地试验区」和数据边界，
  不能只靠角标让用户自己猜。

## 5. 动效规则

- 只用于"状态反馈"一类：hover / 焦点 120ms（`--dur-fast`）+ `--ease:cubic-bezier(.2,0,0,1)`
- 全页仅 3 处 `transition`，无一超过 200ms
- 禁止：弹跳、旋转入场、视差、>400ms 过渡；**高频低新鲜度操作零动画**（按钮 hover 只变色）
- **能力查询写在样式表最末尾**（靠层叠顺序覆盖前面无条件生效的规则）：
  - `@media(hover:none)`：触屏没有真 hover，`:hover` 会"粘"在最后点击的元素上 → 把纯装饰性 hover 收回默认态。**但破坏性行为的 hover 保留**（`.del:hover` 的红色提示不收回），避免误触时失去警示
  - `@media(prefers-reduced-motion:reduce)`：`transition/animation/scroll-behavior` 全部 `!important` 关掉
- 切主题不触发过渡

其他硬规则：

- **金额列 `white-space:nowrap`（必须，不是审美）**：✎/✕ 就挂在金额列末尾，而行内只差 1px 就会把**删除按钮挤到第二行** ——
  实测金额列 90.7px、内容需要 91px，于是行高 56 → 81，且 ✕ 孤零零跑到 ✎ 下面。
  这张表是 auto 布局，只有 `min-content == max-content` 时它才肯把列宽给足，`nowrap` 就是那个开关。
  只读记录不渲染按钮，所以这个缺陷**肉眼与静态检查都看不见**，只有真机点一遍才会现形
  （`scripts/tests/smoke-ux.mjs` 第 I 节有断言守着「同一行 + 行高 ≤60」）

- 🔴 **`white-space:nowrap` 在 grid `fr` 轨道里是相反的结论：禁止。**（2026-09-30 加入，与上一条并读）
  上一条说 `nowrap` 是"开关"，这一条说它"禁止"—— **同一条属性、相反的判定，差别只在容器**。
  这是本契约里最容易照抄出错的一处，所以两条必须挨着写。
  - 为什么危险：`nowrap` 会让元素的 `min-content` **等于整段文字宽度**。实测一段中文摘要在 `nowrap` 下
    `min-content = 968px`；而 grid 的 `fr` 轨道**自带 min-content 下限**——
    于是 `.leftcol` 被顶到 **1234px**、整页 `scrollWidth 1823 > 1440`，横向溢出。
    资讯屏原本要给 20 条摘要，等于把 20 段文字里最长的那段当成了页面最小宽度。
  - ⚠️ **`overflow:hidden` 与 `min-width:0` 都拦不住**，别指望它们。这两个属性管的是
    "**能不能被压缩**"，不管"**min-content 是多少**"。实测（一次只改一处）：
    基线 `.leftcol` 1234px → `.ns` 改 `normal` 684px → `.ns` 加 `overflow:hidden` **仍然 1234px**。
    能真正降下 `min-content` 的只有**换行**（中文可在任意字间断行）。
  - 正解是**两行截断**而不是单行省略号：`-webkit-line-clamp:2` + `overflow:hidden`。
    顺带比省略号有用——两行能看到一倍的信息量。
  - 守它的断言**必须在真机上量几何量**：逻辑测试那套没有排版引擎，只能验"用了不该用的写法"，
    量不出 1823 > 1440。`smoke-ux.mjs` 第 J 节逐屏测 `scrollWidth / 首屏高 / 渲染条数 / .ns 实际行数`，
    四屏 × 两主题全绿（`.ns` 2 行、`nsOver = −4px`）

- **派生数值的取整必须"跟着量级走"，且不许把语义压成同一个数**：快捷预设原用固定
  `Math.round(v/100)*100`，2026-09 实测上月净额 ¥260.87 / 上月 +20% ¥313.04 / 按当前节奏 ¥329.86
  → **三个都变 ¥300**，四个按钮里三个点下去结果一样 ——「加两成」这个语义直接消失。
  规则：步长按量级选（`≥10000→1000 / ≥1000→100 / ≥100→10`，其余 1），
  **并对取整后撞值的项去重**（宁可少给一个参照，也不要摆两个结果一样的按钮）；
  去重若真撞值，`dedupeByValue()` 抽成纯函数以便单独断言 ——
  当前数据不触发撞值，不抽出来这段防御分支就是死代码。
  ⚠️ 断言要落在「**可用的参照有没有变少**」上：`v % 100 === 0` 这类只查**格式**的写法，
  对上面三个 300 全都成立、永远是绿的。**断言选错维度 = 换个说法的不写断言。**

- **阴影即海拔**，错用即视觉谎言：卡片 `sm` / 浮层（跳转链）`md` / 模态与撤销条 `lg`
- **焦点环用 `box-shadow` 而非 `outline`**：`outline` 在旧 Safari 上不跟随圆角
  ```css
  :focus-visible{outline:none;box-shadow:0 0 0 2px var(--card),0 0 0 4px var(--accent)}
  ```
  只在鼠标聚焦时去掉默认轮廓：`input:focus:not(:focus-visible){outline:none}`
- hover / selected **只改颜色不改字重**（防布局抖动）；字重下限 400（无 300 细体）
- 图标：单一风格文字符号（✎ / ✕ / ✓ / ▲ / ▼），16 与 20px 两档
- 禁用按钮不放 tooltip（键盘/触屏永远触发不了 hover）—— 原因写在旁边说明文字里
- **状态提示分两条通道，都不用 `alert()`**：
  - 数据完整性类（保存失败 / 401 / 只读拦截）→ 常驻条 `#notify`，可复制、显式关闭
  - 表单校验类（请填名称 / 金额为负）→ 字段内联 `.ferr` + `aria-invalid="true"`
- **删除不做确认弹窗，做撤销条**：暂存 `{记录, 原索引}`，8 秒内可撤销；撤销必须 `splice` 回**原索引**而不是追加（否则按日期排序的视图会跳）
- 三个整块可点的 `<div>`（来源行 / 体检行 / 项目卡）带 `tabindex="0" role="button"` + **一个** document 级键盘激活委托（一份实现管三处）

## 7. 媒介底线

**目标设备：桌面为主 + 移动可读**（980 / 560 两个断点）。

- 正文 ≥14px；全页无 <12px 字号
- 触控目标：
  - 按 **WCAG 2.2 AA（2.5.8 Target Size Minimum，24×24）** 全部达标
  - 按技能规则库 **A25 的 44×44**：`.del/.edit` 通过伪元素扩展达到 44×44；`.btn`(34 高)、`.pbtn`(30 高)、`.segbtn`(26 高) **未达 44**，这是刻意的密度取舍 —— 它们不是破坏性操作，且页面主要用途是桌面盯数
  - 自媒体页的主折叠标题统一为 **44px 高**；手机上不用瞄准一行 24px 高的文字。内容表现标题最多两行，保留足够的比较信息，不把三张卡都截成同一串省略号
  - 复盘页的工具折叠行与备注历史同样是 **44px 高**；“打开笔记”保持 18px 的紧凑视觉，用伪元素扩成 44px 命中区；项目待办名称在手机上最多两行，避免只剩项目名前半句
  - 资讯、复盘和客户三处的“清除筛选”只在筛选真实生效后出现；默认状态不摆一个无效动作
- 移动端输入框字号：**≤560px 断点下提到 16px（走 `--fs-lg` 令牌）**。
  iOS（Safari 及所有 WebView）在聚焦字号 <16px 的输入框时会**自动放大整页且失焦后不缩回** —— 填一次表单页面就一直是放大的。
  16px 在这里不是设计刻度，是平台的放大阈值；它恰好与 `--fs-lg` 同值，所以用令牌写而不是写 `16px` 字面量
  （直接写字面量会破坏"全页字号走 `--fs-*`"那条纪律，实测被它拦下来过）。
  另注：这条规则的选择器必须与 `​.ledbar input` / `.field input` **同权重**（都是 0,1,1）才能靠"在样式表末尾出现"取胜；写裸 `input` 权重不够，会被压回去
- 键盘：`Tab` 第一站 = 跳转链「跳到主内容」；跳转目标 `<main>` 带 `tabindex="-1"`。
  第二站即 §4.1 的类型切换器（这就是把它放进 `<main>` 的原因：一跳进来就能改类型）
- 屏幕阅读器：3 个 `role="status" aria-live="polite"` 活区（banner / notify / undo）；两个模态 `role="dialog" aria-modal="true" aria-labelledby`；11 个 `<label>` 全部显式 `for=`；今日备忘、目标金额与收益搜索/筛选另有显式 `aria-label`，不只依赖 placeholder；账本 4 个 `<th scope="col">`；类型切换器是 `<nav aria-label="功能类型">` + 8 个 `aria-pressed`（**不是** `role="tab"`，理由见 §4.1）
- 模态焦点由同一套逻辑接管：打开后聚焦首个可操作控件，`Tab / Shift+Tab` 在模态内循环，关闭后回到触发按钮；模态打开期间锁定背景滚动。`aria-modal` 只描述语义，不能代替这道键盘约束。
- 静态 ID 必须全页唯一。数据来源卡片与弹窗曾共用 `srcTag`，弹窗里的来源数量实际写进总览卡片；弹窗自己的标题则一直为空。逻辑层守静态 ID 唯一，真机层守运行时 DOM 无重复 ID。
  - ⚠️ **账本 `<tr>` 故意不进 Tab 序**（每行已有 ✎/✕ 两个真按钮；257 行各加一个停靠点会让键盘用户按几百次 Tab）。这是反向约束，有断言锁着

## 8. 反向约束（本项目明确不做）

- ❌ 不用 `alert()` 做任何错误通道（数据类错误会随点按消失，且不可复制）
- ❌ 不用 `confirm()` 做删除确认（改为可撤销：不打断，且真能救回数据）
- ❌ 不靠"撑大盒子"实现 44px 命中区（会把 257 行账本撑高）—— 用绝对定位伪元素扩
